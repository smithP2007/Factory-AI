ARCHITECTURE
------------
Implement the main pipeline as:

CCTV/video
  -> person detection + tracking
  -> PPE detector (helmet, gloves, goggles, vest)
  -> person↔PPE association
  -> compliance engine
  -> persistent-violation gate
  -> explainable result / evidence

Do NOT make `no_helmet`, `no_gloves`, `no_goggles`, or `no_vest` physical detector classes unless you have verified, genuinely annotated data for those absence/violation classes. For this implementation, missing PPE is inferred by the compliance engine from the worker's associated PPE detections.

PERSON↔PPE ASSOCIATION
----------------------
Implement a worker association stage.

For each tracked worker, determine whether helmet/gloves/goggles/vest detections belong to that worker.
Use worker-relative geometry and confidence, not only global proximity.

Suggested approximate regions:
- helmet: upper ~35% of worker box
- goggles: upper ~45%
- vest: central torso region
- gloves: lower/mid body regions, allowing side offset

Use an expanded worker box to handle small offsets and overlap.
Make thresholds configurable.

COMPLIANCE RULE
---------------
For a standard zone, required PPE = helmet + gloves + goggles + vest.

Worker is compliant only when all four are associated.
Otherwise:
NON-COMPLIANT
Missing: [specific PPE classes]

For the MVP, one confident associated glove detection is treated as evidence of gloves present. Clearly document that this is a simplification; later versions can require left/right glove evidence.

PERSISTENT VIOLATIONS
----------------------
Do not trigger an alert on a single bad frame.
Use a configurable persistence gate. Start with:
- 3 consecutive violating observations -> confirm violation
- 2 consecutive clear observations -> clear state

Make the logic work by worker track ID.
